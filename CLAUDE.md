# CLAUDE.md

Research and portfolio platform for Kancil Capital (student investment fund, University of Manchester). Next.js frontend + FastAPI backend + Supabase, in one repo. It adapts three older Python tools (SentimentPulse, PEAD research, earnings prediction); their logic was rewritten here, never import them as dependencies.

## Commands

- First-time setup is in `README.md`. Everyday commands are in the root `Makefile` (`make help` lists them): `make dev`, `make install` (after pulling), `make generate`, `make lint`, `make check` (lint + type-check + build), and `make db-*` for the database. CI (`.github/workflows/checks.yml`) runs the same checks on every PR and fails if `make generate` wasn't run after an API change.
- Frontend uses `bun`, backend uses `uv`. Never npm/pip.
- Backend commands run from `backend/`; it is the import root (`from core.config import settings`, not `from backend.core...`).

## API contract (frontend ↔ backend)

Frontend types and SWR hooks are generated by orval from the FastAPI OpenAPI spec into `frontend/lib/generated/`. Never edit that folder by hand.

- Every FastAPI route needs an explicit camelCase `operation_id` (e.g. `getResearch`); it becomes the hook name.
- After changing backend models or routes: `make generate`. It exports the spec from the backend code (no server needed) to `frontend/openapi.json`, then runs orval. Commit `openapi.json` with the change so API diffs are reviewable.
- New frontend data fetching uses the generated hooks, not hand-written fetches.

## Database

Full guide: `docs/database_workflow.md`. Database `make` targets need Docker.

- Schema changes are migrations in `backend/supabase/migrations/`, never edits in the production dashboard. Never edit a migration that is already on `main`.
- Preferred: change the local DB in Studio (localhost:54323), then `make db-diff name=<name>` (runs `supabase db diff --schema public`; without that flag Supabase-internal noise like `drop extension "pg_net"` appears). Renames come out as drop + add, so rewrite them as `RENAME` by hand.
- `make db-reset` rebuilds local from migrations + `seed.sql`. Run it to verify a migration, and after every branch switch (otherwise the diff picks up the other branch's changes).
- **Pushing migrations to `main` deploys them to production** (`.github/workflows/db-deploy.yml`). Drops are irreversible, so flag them before pushing.
- Local dev: `.env` holds production values; `.env.local` (backend and frontend) overrides the Supabase URL and keys. `make db-env` / `make use-prod` switch between local and production (they only touch the Supabase variables). Seeded logins: `admin@kancil.test`, `analyst@kancil.test` (password in `seed.sql`).

## Gotchas

- Alpha Vantage free tier: 25 calls/day, 1/second. Always go through `eps_service` (90-day `eps_cache` + throttle); never call it on page load.
- PEAD signals are computed on demand and cached in memory for 12h. There is no table for them.
- Auth: the backend accepts Supabase JWTs signed HS256 (shared secret) or ES256 (JWKS). Local Supabase issues ES256.

## UI conventions

- Skeleton loaders, never spinners.
- Monospace for all financial figures (prices, returns) to stop column jitter.
- Dark theme; tokens in `frontend/app/globals.css`, full spec in `docs/ui_design_spec.md`.
